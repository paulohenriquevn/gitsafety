# Discover-Plan Score Thresholds — per-project tuning.
#
# Authoritative source: rules/discover-plan-golden-rule.md § 5 (verdict tokens).
# Consumed by: skills/discover-plan-confidence/scripts/run_discover_plan_score.py
#              (_parse_thresholds -> _verdict_for)
#
# FORMAT — pipe-delimited, one band per line:
#   NAME|MIN_SCORE|SUNSET|ADR_REF
#
# The parser splits on `|` and reads fields 1 and 2. A line that does not split
# into at least two fields is silently skipped. This is why the format matters:
# a `KEY = VALUE` file parses into ZERO bands, and _verdict_for then falls
# through to its `return "INVALID"` default — every plan scores INVALID with an
# empty hard_caps_triggered list, which contradicts the golden rule invariant
# ("hard_caps_triggered MUST be non-empty when verdict==INVALID").
#
# That exact defect shipped here until 2026-07-27. Regression coverage lives in
# skills/discover-plan-confidence/tests/test_thresholds_parsing.py — do not
# change this format without running it.
#
# Sibling files already using this format:
#   rules/plan-confidence-thresholds.txt
#   rules/discover-blueprint-thresholds.txt
#
# Lines starting with `#` and blank lines are skipped.
# Per-project overrides go here and are CHANGELOG-tracked.
