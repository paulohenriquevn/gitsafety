# Milestone M6 — Publicação no PyPI

## Definition of done

- [x] Pacote publicado no PyPI; instalação funciona em máquina limpa
      — https://pypi.org/project/gitsafety/0.6.0/ ; validado com `pip install gitsafety`
      em venv virgem: versão certa, uma dependência (PyYAML), `scan` achando, hook
      bloqueando commit, `--history` achando o segredo removido.
- [x] README confere com o pacote — **mecanizado** em
      `tests/functional/test_package_metadata.py`, nas duas direções.
- [ ] `CHANGELOG.md` com a versão `1.0.0` — **deliberadamente não cumprido**, ver ADR 0002.

## A divergência, explícita

O DoD pedia `1.0.0`. O `dogfood-golden-rule.md § 3` dispara `EVIDENCE_INSUFFICIENT` porque
não há manifesto de dogfood, e `public-copy.md § 3` veta a alegação de v1.0 sem evidência
de uso sustentado. Golden rules são travadas; o roadmap não é. Publicado `0.6.0`.

1568 testes e cinco rodadas de review adversarial são evidência de **corretude**, não de
**uso**. São coisas diferentes, e o gate existe para não confundi-las.

## O que a validação em ambiente limpo pegou

`gitsafety --version` imprimia **0.4.0** num pacote **0.6.0** — a versão estava escrita em
dois lugares e divergiu sem nada para acusar. Num produto de segurança a primeira coisa que
se pede a quem reporta um problema é a versão. Corrigido eliminando a duplicação
(`importlib.metadata`), não sincronizando.

Faltava `[project.urls]`: a página no PyPI não teria link para o código.

## Caminho para o 1.0.0

Criar `knowledge-base/dogfood/manifest.md` com um cenário-âncora, usar a ferramenta em
trabalho real, registrar evidência, rodar `/dogfood`. Enquanto o veredito não for
`EVIDENCE_SUFFICIENT`, o `1.0.0` segue barrado.
